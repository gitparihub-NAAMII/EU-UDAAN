## How we are approaching it

1. **Experience first, theory second.** Every module starts from a real farm situation: Experience → Observe → Discover → Practise → Apply.
2. **Problem-based learning on real agricultural problems,** using the UDAAN U0–U4 framework: formulate → describe → diagnose → predict → decide and act.
3. **Individual ownership, group integration.** Each learner owns one subproblem, each group builds one component, and all ten connect through a common data foundation and agent architecture.
4. **One shared GitHub repository.** 10 group branches and 40 member branches, with reviewed pull requests, so every contribution is traceable.
5. **Self-study on the platform, workshops for practice.** 40 hours on Tangible Careers/Shikshya.org; trainers spend their 20 hours on guided practice and review.
6. **Evidence and human review built in.** Sources and data limits are documented, and agent recommendations go through a Reviewer and human validation.

## Why this approach

| Choice | Why |
|---|---|
| Start from agriculture, not code | The learners are IT students: their gap is understanding farming systems, not programming. |
| 40 per cohort, 2 trainers | 20-learner cohorts would use 94% of trainer time with no slack; 40 uses about 48%, leaving room for dropouts, festivals and reruns. |
| 40 h self-study / 20 h workshop | Trainer time is the limit (about 1,600 trainer-hours over 24 months); only workshop hours use it. |
| Groups of 4 with one subproblem each | Balanced skills, clear individual accountability, and a component big enough to matter. |
| One integrated system, not 10 apps | Avoids "ten unrelated chatbots"; mirrors how AI is used in real organisations, and gives a showcase product. |
| U3 only where data supports it | Nepal-specific historical data is limited; no unsupported predictions. |
| Pilot before scale-up | The team agreed to launch the full AI Foundation module only if the first cohort works well. |

## Success looks like

All ten groups understand their agricultural system and complete a U0 problem; the cohort builds a reusable Agricultural Data Foundation; each group delivers a working agent or tool-using workflow; contributions are integrated through reviewed pull requests; and the final prototype is demonstrated and evaluated.

**Assessment:** agricultural understanding 10% · workflow mapping 10% · U0 formulation 15% · Problem Bank 15% · data and intelligence requirements 15% · agent design 15% · working prototype 20%.

**Key risks:** limited Nepal data (combine sources, document limits) · too-complex agents (start simple, then expand) · groups building disconnected apps (common data standards and interfaces) · workshop support (add a teaching assistant or split sessions).
