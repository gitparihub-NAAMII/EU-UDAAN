# UDAAN Project Tracker

This folder is where the Education and Outreach team plans and tracks its work. From now on everyone works from these files and pushes their changes to GitHub. The files are the source of truth; the dashboard and any Excel summary are built from them.

## What is in the folder

| File | What it holds |
|---|---|
| `team.md` | Who does what, and each person's current focus |
| `goals.md` | Weekly, monthly, quarterly and yearly goals with progress |
| `weekly-plan/` | One file per week (named with the Monday date), one section per person |
| `targets.md` | Each person's targets and what was reached |
| `todo.md` | Everyday tasks for the team |
| `deliverables.md` | Documents, modules and reports that must exist when finished |
| `challenges.md` | What is getting in the way and what is being done |
| `risks-and-decisions.md` | Risks, decisions and follow-ups |
| `meeting-notes/` | Notes from team meetings, using `TEMPLATE.md` |
| `GUIDE.md` | Step-by-step guide for editing and pushing |

## Rules the team follows

1. Edit only your own rows or your own section. If a row belongs to someone else, ask them or add a note in `todo.md`.
2. Pull the latest version before you start editing.
3. Push before the Monday check-in. Sumi checks that everyone has pushed.
4. Use the allowed values: Status is Not started, In progress, Done, Blocked or At risk. Priority and severity are Low, Medium or High.
5. Write dates as `31 Dec 2026` and progress as a percentage, for example `25%`.
6. Never delete another person's row. Mark finished work Done.
7. Write a clear commit message, for example `Update Pradeep's weekly plan`.

## Each Monday

1. Sumi copies `weekly-plan/TEMPLATE.md` to a new file named with that Monday's date.
2. Everyone fills in their own section of the new weekly plan and updates their rows in the other files.
3. Everyone pushes, and the team reviews at the check-in.
