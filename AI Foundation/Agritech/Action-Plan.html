Part I · Programme design

Programme overview

The programme helps IT students understand agricultural systems and build AI-enabled solutions for real agricultural challenges. Each of ten groups investigates one agricultural problem. Each member builds one related component, and the group integrates the four into a specialised intelligence system. All ten projects share a common Agricultural Data Foundation, common utilities and knowledge resources, and are finally connected through a common Agentic AI architecture.

UnderstandExplore agricultural systems, workflows, stakeholders and available data.
FormulateIdentify and structure agricultural problems.
BuildDevelop analytics, knowledge retrieval and specialised agents.
TransformIntegrate into an AI-enabled workflow and evaluate the prototype.

Expected competencies

  • Understand agricultural systems, workflows, stakeholders and value chains.
  • Identify agricultural information and data requirements.
  • Explore, acquire and prepare agricultural datasets.
  • Establish an evidence-aware Agricultural Data Foundation.
  • Formulate problems with the eight elements of U0.
  • Run descriptive, diagnostic and predictive analysis.
  • Organise agricultural knowledge for retrieval; use local LLMs and RAG.
  • Design specialised agents and tool-using workflows, coordinated by an Agent Manager.
  • Implement validation and human-review mechanisms.
  • Integrate, test and demonstrate a prototype.

Groups and agricultural themes

Before groups form, participants complete a skills survey (Python, data and databases, AI/ML, documentation, Git). Trainers then build ten balanced groups of four with a mix of programming, data, analytical and documentation skills.

Experience first, theory second

Each lesson starts with a realistic agricultural situation or workplace task, not a theoretical explanation. Participants meet a challenge, observe it, discover the concepts they need, practise the skills and apply them to their group project. Theory arrives when it is needed.

1. ExperienceEncounter a realistic scenarioWhat is happening in the real world?
2. ObserveIdentify the challenge and information gapsWhat do we notice?
3. DiscoverConcepts, methods, technologiesWhat do we need to understand?
4. PracticePractise skills with examples and toolsHow can we do it?
5. ApplyUse the skills on the group projectHow do we apply it to our problem?

Example: introducing agricultural data

The instructor does not begin with CSV, databases, APIs or data types. Instead:

  1. Experience: a cucumber farmer reports fruit damage but keeps no systematic records.
  2. Observe: learners suggest what information would help.
  3. Discover: observations, measurements, records, data sources, variables and data quality.
  4. Practice: inspect and organise sample farm records and weather datasets.
  5. Apply: each group identifies and prepares the datasets for its own theme.

Every lesson plan and self-study unit names the scenario, the challenge, the concepts, the skills, the group-project task and the expected evidence or deliverable.

Part III · Common project infrastructure

Shared Agricultural Data Foundation

A cohort-wide resource, not an application owned by one group. It reduces duplication and sets common data standards.

Three data layers

1 · External & publicPublic datasets, APIs, government and institutional sources
2 · Knowledge repositoryResearch, manuals, extension publications, crop calendars, expert-reviewed documents
3 · Primary & simulatedSurveys, field observations, soil tests, farm records, sensors, simulated data

Every dataset is labelled as observed, externally sourced, derived or simulated.

Every shared dataset documents

  • Name and description
  • Original source
  • Geographic coverage
  • Observation period
  • Spatial and temporal resolution
  • Variables and units
  • Collection method
  • Quality limitations
  • Licence or access conditions
  • Observed / sourced / derived / simulated

GitHub collaboration workflow

A two-level branching model: main → group-NN → member-NN.

  1. Trainers create the central repository and the shared folder structure.
  2. Each group creates its branch from main.
  3. Members create individual branches from their group branch.
  4. Members commit and open pull requests to the group branch.
  5. The group coordinator reviews and integrates contributions.
  6. The group opens a pull request to main.
  7. Trainers review and merge approved work.

No direct commits to main. A branch holds the whole repository, so members change only their group folder unless authorised to edit shared resources.

Both trainers maintain the repository, data standards, architecture and integration requirements, and prepare the repository, sample datasets, materials and scenarios before the programme begins.

Assessment

Assessment measures the ability to understand and improve agricultural workflows, not coding alone.

Individual work is evidenced through documentation, commits, pull requests, reviews and the ability to explain it. Group assessment covers integration quality, evidence, analysis and the demonstration.

Success criteria

  1. All ten groups understand their agricultural systems.
  2. The cohort establishes a reusable Agricultural Data Foundation.
  3. Data sources and limitations are documented.
  4. Each group completes an eight-element U0 problem formulation.
  5. Each group completes relevant U1 and U2 work.
  6. U3 is completed where data permits, or its limits are documented.
  7. Each group builds a knowledge retrieval capability.
  8. Each group implements a specialised agent or tool-using workflow.
  9. The final system shows agent coordination and validation.
  10. All contributions are integrated through reviewed pull requests.
  11. The final project can be demonstrated and evaluated.
  12. Individual contributions are traceable.

Final programme outcome

Not ten independent chatbots or unrelated AI apps, but one integrated Agricultural Agentic AI project with:

  • A shared Agricultural Data Foundation with common geographical and environmental resources.
  • Agricultural knowledge resources.
  • Ten specialised agricultural intelligence components.
  • Common interfaces and reusable tools.
  • An Agent Manager, plus a Reviewer and human-validation workflow.
  • A demonstrable, evaluated prototype.

Start with real agricultural experiences. Help participants observe and understand the agricultural system. Introduce data and concepts when they become necessary. Let participants practise the required skills and apply them to their own agricultural problems. Build the common data foundation, develop specialised intelligence, and integrate the results into one Agricultural Agentic AI system.

Experience first. Theory second. Application throughout.
